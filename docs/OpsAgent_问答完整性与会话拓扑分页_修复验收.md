## 回答完整性

- Chat Completions 检查 `finish_reason` 和流终止标记；OpenAI Responses 检查 completed/incomplete 等终态。
- `length` 才触发有限续写；网络中断、内容过滤、续写失败或达到续写上限时，返回可用正文与明确状态，不标成完整回答。
- 结果元数据新增 `generationComplete`、`finishReason`、`continuationCount`。智能问答和工单 AI 均展示结果完整性，错误提示不会覆盖已经收到的正文。
- SSE 超时与续写预算同步；完成会话持久化后才发送 done，保存失败不显示成功。
- 前端正确处理分片中文、跨分片 CRLF、JSON 业务错误及缺少 done 的提前断流。
- 共用回答展示组件支持标题、加粗、行内代码、代码块、表格、列表和分隔线，输出按 Vue 节点转义，模型文本不会直接作为 HTML 执行。

## 会话管理

- 新增 `rag_conversation` 与 `rag_conversation_turn`，迁移文件为 `sql/13_rag_conversations.sql`，已应用到本地现有 MySQL。新环境随项目 SQL 初始化执行。
- 所有会话接口从服务端认证身份读取账号 ID。即使两个账号都是管理员，也不能互读、重命名或删除对方的会话。角色用于权限控制，不作为共享聊天记录的分组。
- 问题、正文、引用、模型和完整性状态保存在后端；刷新和重新进入后可恢复。会话列表每批 20 个，消息每批 20 轮，支持加载更多。
- 连续追问使用最近最多六轮已完成历史，并限制上下文长度；历史用于理解对话，不冒充知识证据。
- 对“刚才、上面、它、继续、某一步”等明确指代，回溯最近独立主题辅助检索与重排；新独立问题可以正常切换主题。对话回顾不能被新检索到的其他组件资料改写。
- 单个会话通过数据库事务和行锁限制同时生成；超时、连接中断和逻辑删除后的回调均处理状态，避免覆盖其他轮次。
- 前端同步会话 URL，切换历史和加载旧消息使用请求版本检查，避免迟到响应覆盖当前会话。

历史保存从本次更新开始生效。此前从未保存到后端、且已经清空或随页面关闭丢失的记录，无法凭本次改动补回。

## 拓扑与 SLA

拓扑保留真实服务目录、详情、编辑和新增依赖接口，显示直接关联，不伪造多跳关系。支持节点切换中心、关联线高亮、拖动、键盘平移、缩放、适应画布、类型图例和完整关系清单。孤立节点和加载失败采用不同状态；配置登记状态不解释为实时健康。

SLA 新增 `/api/tickets/sla/page` 和 `/api/tickets/sla/summary`。后端执行 count、稳定排序和 limit/offset，保留旧 overview 接口兼容性。运行总览改用全量风险聚合，同时保持其原有风险口径。分页支持服务、优先级、风险与关键词过滤。
