# 事件驱动的 AI 运维工作区

日期：2026-09-06。状态：已完成并发布，最终变更与验收见 event-workspace-release-report.md。

## 产品范围

主线为发现异常、形成事件、证据诊断、审批执行、业务验证、经验沉淀。复用现有工单作为事件处置载体，保留告警、执行运行和人工记录各自的身份，不另建重复工单体系。保留现有 Spring Cloud 服务和蓝白视觉风格。

## 三阶段

1. 收敛入口：运行总览、事件处置、自动化中心为主要入口，服务与观测、知识与经验为支撑入口。问答作为全局助手，协作和管理能力进入明确可达的二级入口，旧链接兼容。事件详情以处置工作区为默认视图，原附件、问答、人工记录和活动保留。
2. 提升证据质量：同一事件聚合授权范围内的运行、审批、变更、模型诊断和恢复记录；区分事实、假设和证据缺口，区分近期相关变更与已证实原因，区分历史恢复与当前目标健康。工作流结束不等于业务恢复。现场工具投影不主动注入故障场景标签；授权运行手册仍可检索引用，结论需比对真实证据。
3. 扩展真实场景：增加隔离的消息消费目标及 RabbitMQ 积压场景，沿用精确审批、版本校验、幂等、过期恢复和业务验证。平台核心队列和数据不参与故障注入。以真实消息/消费/积压数据验证新工具能力，同时保留不支持/证据不足时转人工的路径。

## 实施边界

所有正式代码位于 D:\myselfProject\opsagent。过程日志、打包、会话和验收证据位于被 Git 排除的 data/public-deploy。本轮不清库、删卷或改写历史失败运行。权限沿用服务端校验，查看公开工单不等于查看他人的私有 Agent 运行。

## 验收要求

完整 Maven verify、前端构建及有意义状态/权限/关联/恢复回归；尽可能执行真实浏览器交互验证，工具不可用时明确记录边界。云端发布前保存数据库和附件备份，确认目标健康且没有活动运行，再增量部署。至少验证原配置场景、新消息场景、精确审批、真实业务恢复及平台健康。所有成功结论必须有对应记录与实测证据。
