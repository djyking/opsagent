## 改造结论

这一轮围绕“发现风险 → AI 诊断 → 处置与协作 → 验证与知识沉淀”组织能力，保留 Spring Cloud 微服务及现有业务数据。

主要变化是统一运维入口、让 AI 读取真实运行证据、提供可切换的已配置模型，以及加入能记录过程和结果的巡检与隔离演练。没有把现有应用换成静态展示页，也没有通过增加菜单宣称具备尚未实现的自动运维能力。

本地源码仍在 `D:\myselfProject\opsagent`。生产前端为 Vue 构建产物，经 Nginx 与 `/api/` 同源提供服务，不依赖本机 5173。公网更新采用增量源码/镜像及独立工作流表，不重新导入本机数据库覆盖云端业务记录。

## 已实现的功能细节

### 运维中心与真实证据

- 汇总六个 Java 服务抓取状态及 CMDB 归属，并在统一页面查看目录、关系和依赖拓扑。
- 指标保留窗口、样本数、最近采样时间、当前值、预测值、方法和不足原因；缺失服务与缺失序列显示未知。
- 风险提示与覆盖范围说明分开：`INFO` 不计为故障。Prometheus 抓取失败不直接等同于业务进程已停止。
- AI 获取筛选后的证据快照，不获取配置密钥、配置全文、Docker 控制凭据或任意脚本执行权。

### AI 模型与会话

- 默认模型仍为 DeepSeek `deepseek-v4-flash`；选定模型随请求与回答元数据保存。
- OpenAI 当前配置为 `gpt-5.6-luna`，真实探测已确认可达；模型目录“已配置”与请求时能否成功区分表达。
- Kimi 当前未配置，界面显示不可用；没有虚构其连通性。
- 运行数据回答加入 `/operations` 来源链接及采集时间；会话回读保留正文、模型、引用和状态。
- 保留原有知识问答、服务清单、工单和附件范围检索、rerank、完整 SSE 收尾及全局 AI 预算。

### 索引修复

- 失败任务返回源文档名称、当前版本、发布/解析状态、是否可修复及原因；已删除、旧版本或已经恢复的失败记录进入历史区。
- 支持 INDEX 与 DELETE 两种任务的正确重试，禁止把已重新发布文档的旧删除任务重放。
- 修复时校验文档已发布、完成解析且有切片；同一文档的并发请求复用活动任务。
- 一致性不再仅以数量相减：分别核对真实文档 ID、切片 ID 和索引发布标记。合法草稿预索引不误报为孤儿。
- 全量重建说明 API 调用、资源和存储影响，创建新索引并在校验后切换；不删除源文档和既有索引。

### 工作流与访客权限

- `HEALTH_CHECK`：真实采集 → 规则诊断 → 二次验证，仅查询 Prometheus 与 CMDB。定时巡检不调用付费模型。
- `ISOLATED_DRILL`：基线检查 → 固定故障注入 → 实际异常检测 → 固定恢复 → 再次验证。步骤和审计写入 `ops_platform` 的独立表。
- 执行异常保留受控错误代码和脱敏证据；实验故障有自动恢复期限，进程中断后不会偷偷续跑旧演练。
- 当前单平台实例一次执行一个工作流，调度忙碌时跳过，不积压执行队列。将来扩容多个平台实例需增加共享执行租约和实例归属恢复。
- `user / user` 是受限访客入口，不是共享管理员账户。验证码通过后发放 30 分钟临时身份，无 refresh token；重新登录不复用其他访客的历史。
- 访客可浏览业务和使用自己的 AI 会话，不能创建工单、运行处置、维护知识索引、管理模型或编辑配置。公开注册继续关闭。

## 当前明确边界

本轮实现了运行证据接入、规则趋势提示、AI 解释、固定巡检和隔离故障恢复。没有接入 Kubernetes，没有宿主机磁盘/容器统计预测，没有任意流程编排器，没有让 AI 自动执行生产命令，也没有承诺能准确预知故障。

最终实测 AI 回答的指标表、来源和保存结果正确，但建议部分出现了在无外推值时自行按斜率补算、“无实际操作风险”及末段趋势概括范围过宽的表述。它们没有触发任何系统操作。运维结论应核对来源中的逐项实测值与观测范围；当前不能将自然语言建议当作已经验证的生产决策。该已知限制已保留在私有审计记录，未用重复生成更好看的回答掩盖。

真实生产告警与工单仍沿用原有能力；趋势提示不自动宣称已完成故障处置。后续若增加 Docker/node_exporter/cAdvisor 或生产处置工具，需要分别设计采集范围、授权、回滚和验证，不能由当前实验演练的成功推导为生产自动恢复已具备。
