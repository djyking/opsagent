# OpsAgent 内页设计方案

设计基准：2026-09-05 用户认可的动态登录页。先完成本设计，再修改应用源代码。

## 视觉方向

延续登录页的浅蓝画布、白色卡片、蓝灰文字、细边框与柔和阴影。运维工具的任务区域保持清晰和紧凑；装饰集中在导航与页首，真实数据占据主体。现有登录页作为基准保留。

| 设计项 | 内页约定 |
| --- | --- |
| 画布 | #f0f6fe，页顶轻浅蓝、远端少量浅青，不使用大面积深色背景 |
| 文字 | 标题 #234366，正文 #34506e，辅助 #667e97；正文沿用现有系统字体 |
| 主色 | 沿用 #4b6fe7；成功、告警、危险继续使用语义颜色 |
| 容器 | 白色，边框 #dce7f3，16px 卡片圆角，20px 重点容器，轻蓝阴影 |
| 控件 | 38px 常规、32px 紧凑，10px 圆角，明显焦点，次要操作白底细边 |
| 排版 | 页标题 26/34，区块标题 16/24，正文 14/22，辅助 12/18；表格保持业务密度 |
| 间距 | 主区 28–32px，区块 20px，卡片内 20–24px；手机 16px |
| 动效 | 悬停、焦点和展开反馈；数据页无自动轮播，无装饰性持续运动 |

## 导航与框架

将图标轨道与切换式二级栏合并为一套有名称的侧边导航。品牌区与登录页一致，分为工作台、运维协作、AI 与知识、系统管理；菜单位置稳定，当前项使用白色浮起卡片与蓝色图标。保留折叠和手机抽屉、账号身份和退出入口。管理员入口仍按真实角色显示。

主区顶部为当前分组/页面路径、工单搜索、创建和通知；不写死“服务正常”。监控入口通往真实监控页面。页首提供统一图标、标题、简短说明与操作区。焦点工作区仍允许充分使用横向空间。

## 页面设计

| 页面 | 结构与重点 |
| --- | --- |
| 运行总览 | 温和的当班工作摘要，重点事项卡，独立指标卡；活跃工单为主、关注事项为辅；健康、分布、活动分卡展示 |
| 工单中心 | 紧凑页首与统计、稳定筛选条、白色任务表格；突出标题、责任与状态，保留创建/筛选/分页/详情 |
| 工单详情 / 结构化处置 | 清晰身份区、统一页签、主任务与辅助上下文；活动时间线使用主内容空间，保留诊断、审批、执行、验证、记录 |
| 告警 / SLA / 值班 | 独立摘要卡 + 业务列表或排班卡；风险使用局部语义色，表单与弹层沿用公共几何 |
| 服务目录与拓扑 | 浅色目录、网格拓扑画布、服务摘要卡形成清楚的三个区域；窄屏按内容重排 |
| 系统监控 | 服务健康摘要、指标和监控目标卡；数据与依赖状态形成清楚分区，避免靠无意义大块留白撑页 |
| AI 能力中心 | 静态任务介绍与轻量产品图形、快捷任务和能力白卡；入口清晰，不要求持续动画 |
| 智能问答 | 左侧会话、中央问题和回答、右侧引用；空白欢迎态沿用登录页的浅蓝风格，对话后回归内容优先 |
| 知识库 | 库目录、文档主列表与信息/上传入口；柔和选中态，文档状态和操作统一 |
| 知识审核 / 索引管理 | 共用页首、统计和表格/流程卡；保留审核、索引、重试、召回配置等原能力 |
| 通知 / 操作审计 | 筛选与记录表面一致，详情抽屉保持明确层级和可读性 |
| 注册 / UI 基础页 | 注册延续登录品牌，基础页更新为可检查的组件样本 |

## 实现顺序与边界

1. 在 tokens.css 内定义内页主题，在原有基础样式中调整控件、Surface、页首；不在总 CSS 尾部追加整站补丁。
2. 合并导航框架并保留路由、角色和真实接口。
3. 按运维、AI/知识、监控/拓扑三个页面组迁移，最后整合总览与公共弹层。
4. TypeScript、生产构建、Maven 验证；浏览器检查全路由、关键跳转与真实数据，在 1440/1920 和手机宽度检查布局。
5. 仅更新前端服务；截图、设计过程与验收记录放在项目内已忽略的 ui-experience-final 目录。设计文档与源码可随项目提交。

不以样例数字替代真实指标，不改写授权/鉴权规则，不移除已有业务操作，不依赖新的外部 UI 服务或素材库。
