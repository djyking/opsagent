## 2. 本轮实际改造

### 真实故障、监控与工单

- 新增独立订单目标服务及独立 Redis。专用 Nacos 配置漂移导致真实订单请求返回 HTTP 503，Sentinel 规则回退导致真实限流 HTTP 429；恢复动作只作用于这个隔离目标。
- 持续业务探针接入 Prometheus 与告警链路，使用告警 episode、投递幂等、乱序恢复保护和服务端演练归属，关联本次事件、工单与 Agent 运行。
- 工单写入绑定版本与幂等请求。`ticket_resolve` 有界等待连续三次新鲜业务成功探针及告警恢复，必要时按 `CREATED → ASSIGNED → PROCESSING → RESOLVED` 推进工单；配置发布回执或模型文字不能替代恢复验证。
- 旧运维中心的演练入口汇聚到自动化工作区，保留持续巡检；补齐工单来源、Agent 运行链接及 RabbitMQ 服务目录入口。

### 原生 Agent 与持久工作流

- 模型通过原生 Chat Completions `tool_calls` / Responses `function_call` 返回工具计划，普通文本不会解析成执行命令。RAG 层统一处理模型能力验证、预算与调用回执，知识检索复用当前身份的数据权限。
- 保存运行快照、节点输出、模型意图、工具请求、审批、事件和 outbox，结合数据库租约、fencing、RabbitMQ 唤醒及扫描恢复推进运行。模型结果未知时保留同一调用回执，不隐式重发新的付费调用。
- 修复动作必须通过绑定调用 ID、参数摘要、修订及期限的精确审批；每一步复核当前身份和有效角色。暂停与取消在步骤边界生效，不能撤回已发出的远程动作；继续不会重置预算或期限。
- 默认流程为 `开始 → Agent 诊断与处置 → ticket_resolve 显式复核 → 结束`。工作流草稿经过后端校验，发布后保存不可变运行快照。

### 本轮验收中补齐的缺口

- 工具结果送给模型前执行确定性字段投影与长度约束，新模型意图登记前执行上下文预算校验和有界压缩。完整工具结果仍保留在 observations 与事件中；原生工具调用配对及已登记模型请求不变，运行 Token 预算仍为 32,000。
- 当前 Agent 节点已通过真实工具验证解决工单，且直接后继为显式 `ticket_resolve` 节点时，在全部待执行调用处理完毕后进入复核，不再强制追加模型文字总结。节点完成事件标记 `completionSource=VERIFIED_TOOL_RESULT`，不伪造模型 `FINAL` 或 AI 摘要。进入显式复核时重新读取目标、业务探针、告警和工单。
- 修复严格 `Accept: text/event-stream` 请求下的权限错误响应协商问题，拒绝结果保持明确的 JSON HTTP 401/403，未放宽流端点权限。
- 知识列表与文档内容访问沿用公开发布条件及关联工单可见性检查，避免列表可见但正文被拒绝的策略不一致；发布后本人及跨账号只读权限复核结果见第 5 节。

### 自动化工作区

- 提供真实故障演练、运行中心、工作流与版本、模型与工具四个入口；按本次 `incidentId` 跟踪演练，按 `ticketId` 筛选运行，展示真实图连线、条件分支、审批参数与事件证据。
- 审批、人工输入、暂停、继续、取消与演练操作接入真实 API；高风险恢复按钮受目标状态、当前所有者、版本与冷却期约束。
- “已验证解决”要求后端工单解决标记为真、最新 `recoveryVerification.resolved === true`、`toStatus` 为 `RESOLVED/CLOSED`，且运行状态为 `COMPLETED`。后置复核失败时保留“工单曾记录为解决”的事实，明确提示待复核；恢复等待不再被旧成功标记隐藏，AI 摘要不替代验证结论。
- 页面当前约每 4 秒轮询并按事件序号增量读取。后端具备可按序号补发的 SSE 端点，但前端尚未使用 SSE；不能宣称前端 SSE 连接与重连已验收。

## 6. 当前能力边界

本轮交付的是固定隔离目标上的原生 Agent 与持久工作流执行基础。以下范围需要在演示和后续开发中保持明确：

- **固定 8 个工具、单一目标。** 注册工具为 `ticket_get`、`ticket_history`、`demo_target_inspect`、`demo_config_restore`、`demo_flow_restore`、`knowledge_search`、`ticket_add_analysis`、`ticket_resolve`。不支持任意 Shell、SQL、URL、Docker socket、MCP 插件市场或任意生产主机操作。
- **JSON 图编辑。** 当前提供 JSON 定义、后端校验、版本发布与真实运行连线；支持的节点为 START、END、AGENT、LLM、TOOL、RAG、CONDITION、SET_VARIABLE、APPROVAL、HUMAN_INPUT。没有通用拖拽、画线、节点配置面板或并行任务编排器。
- **单一内置流程。** 默认提供 `isolated-recovery`，没有完整独立 Agent 管理界面、三个业务 Agent 产品，也没有完整复盘到知识草稿、审核发布、再次检索的自动沉淀链路。现有知识库与本次发布的手册不等同于自动学习或无限长期记忆。
- **恢复来源须如实展示。** `AGENT_TOOL`、人工恢复与 `TTL_GUARD` 分开记录；保护机制或人工恢复不能计为 Agent 自主修复成果。运行结束、工单曾解决和最新业务恢复验证是不同事实。
- **保留预算与副作用边界。** 运行最多 12 轮模型决策、18 次工具调用、32,000 Token，并受期限约束。UI Token 是执行预算计数，供应商用量未知时保守扣减，不是精确计费账单。暂停/取消不能撤回已发出的动作，未知模型结果不会隐式触发新的付费重试。
- **结构化输出与可观测性仍有范围限制。** 固定工具参数有严格校验，LLM 文本节点尚无通用业务输出 JSON Schema 校验；尚未齐备独立 Agent/Prompt 版本链、完整 Tool/Approval/Workflow 指标和专属 Grafana 仪表板。已有事件与审批轨迹不代表原方案所有生产级 DoD 均已完成。

原始实施方案的全部生产级要求不能据此报告视为完成。已通过项目以第 5 节列明的实际范围为准，真实浏览器截图仍按未完成状态保留。
