## 实施范围

保留现有蓝白风格和 Spring Cloud 架构。执行记录筛选、工单问答、结构化处置、回复统一为白底卡片正文；观察窗口保持标签和下拉框同一行。

模型决策仅在已登记的只读调用内做有限重试，不能重复执行工具或跳过动作审批。明确失败分类和中文建议，持久 UNKNOWN 不通过“继续”静默重复请求。

配置中心接入现有 Nacos：纳管 `OPSAGENT_DEMO/ops-demo-order-business.json` 的目录标题、业务提示及演示折扣，目标订单预览真实使用配置。运行配置 `ops-demo-order-runtime.json` 只读，由原演练、审批、TTL 流程管理。管理员可校验、预览差异、发布及回退；普通用户和访客可查看。页面区分 Nacos 当前版本、目标应用版本与真实业务返回。

发布采用精确版本校验、Nacos CAS、请求幂等、目标互斥和持久审计；与演练及冷却期互斥。回退创建新版本，保留已有记录。原文件中的凭据及平台核心连接配置不对前端开放。
