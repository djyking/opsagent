# OpsAgent 事件工作区新版变更与验收记录

版本：event-workspace-20260906-r2。日期：2026-09-06。

## 本轮产品变化

1. 收敛为三个主要入口：运行总览、事件处置、自动化中心。服务与观测、知识与经验作为支撑入口，AI 助手与审批收件箱在全局可达；SLA、值班、原始告警、配置和知识审核保留明确二级入口，兼容旧链接。
2. 复用现有工单作为事件载体，点击事件默认进入处置工作区。一个页面集中查看事件阶段、事实、候选原因、证据缺口、相关变更、审批、运行和业务验证。原人工记录、附件与问答仍保留。
3. 运行总览显示服务端按身份统计的全量运行数据。最近运行的恢复效果仅代表最近十次样本，缺失或失败的读取不会被显示为零故障或已恢复。
4. 自动化中心统一运行与审批、流程版本、持续巡检、模型工具和故障演练；手动发起入口折叠。修复深链刷新、切换页签被旧请求抢回的导航问题。

## 诊断与恢复质量

- 新增当前事件的授权证据聚合 API，以及按账号/管理员范围统计的运行摘要 API。
- 关联 Nacos 配置版本、变更前后值、事件时间和真实业务探针。相关变更只作为候选证据，不直接等同根因。
- AI 诊断保存事实、候选原因和证据缺口；现场工具投影不主动注入故障场景标签；模型仍可检索已授权的运行手册，并需比对实际配置、变更和业务观测。
- 修改动作仍要求绑定目标、事件、版本与精确参数的审批。运行完成、人工恢复、到期保护与 Agent 修复分别记录。
- 当前恢复要求本事件匹配、新鲜探针连续成功与告警恢复。通知目标还要取得消费回执、Redis 读回和队列排空。历史恢复不代表目标当前健康，页面观测过期会降级提示。
- 复盘草稿根据已保存证据整理，可编辑并存为私有关联文档，解析和人工核对后进入知识审核。不会自动公开或伪造根因。
- 跨账号与跨事件晚响应被丢弃；明确的参数拒绝可调整重试，回执未确认的创建复用原请求，复盘上传结果不明时阻止重复提交。

## 第二类真实目标与故障

新增隔离通知服务及独立 RabbitMQ broker。暂停专用消费者后，真实消息形成积压并触发监控告警、事件和 Agent 处置；恢复工具重新订阅，随后验证本次消息投递、隔离 Redis 回执和队列排空。保留订单服务的配置漂移与 Sentinel 限流场景。

通知与订单共用原 Demo JVM，各自维护事件租约与配置；RabbitMQ 容器限额 256 MiB、绝对水位 192 MiB、关闭非必要插件，不发布公网端口。故障注入不涉及平台公共消息队列。
