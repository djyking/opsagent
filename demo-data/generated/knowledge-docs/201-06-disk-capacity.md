# 生产服务器磁盘使用率告警处置手册

## 适用范围

本手册适用于 Linux 生产服务器根分区、应用日志分区、容器数据目录和 OpsAgent 上传目录的磁盘使用率告警。磁盘使用率达到 85% 应开始排查，达到 90% 应按高优先级处理；inode 使用率达到 90% 即使磁盘容量尚有剩余也可能导致文件创建失败。

## 一、先确认告警是否真实

1. 使用 `df -hT` 核对告警分区的容量、已用空间、挂载点和文件系统类型。
2. 使用 `df -i` 检查 inode，区分“大文件占满空间”和“大量小文件耗尽 inode”。
3. 对比告警前 30 分钟、当前和历史同周期曲线，确认增长是否持续，不依据单个瞬时值直接清理。
4. 记录主机、实例、挂载点、开始时间、当前使用率、增长速度及受影响服务，并在工单中持续更新。

## 二、定位空间来源

在目标挂载点内逐层使用 `du -xhd1` 查找大目录，避免跨文件系统扫描。重点检查应用日志、临时目录、上传目录、容器日志、数据库备份和未清理的发布包。使用 `find` 查询大文件时应限制挂载点和目录范围，避免全盘扫描造成额外 IO 压力。

若文件已删除但空间没有释放，使用 `lsof +L1` 检查仍被进程持有的已删除文件。此时应评估业务影响后滚动重启对应进程释放句柄，不要直接重启整台生产服务器。

## 三、安全处置顺序

1. 暂停非必要的日志导出、离线任务、备份或大文件上传，先降低增长速度。
2. 按日志保留策略压缩或迁移已归档日志；禁止直接删除当前正在写入的日志文件。
3. 清理明确可重建的临时文件、过期发布包和超过保留期的备份，清理前记录目录、时间范围和预计释放空间。
4. 容器环境先确认具体容器和日志驱动，再处理超大容器日志；不得直接删除 Docker 数据目录或数据库数据文件。
5. 容量仍不足时执行已评审的磁盘扩容或数据迁移方案，并保留回滚路径。

## 四、风险与升级条件

根分区超过 95%、数据库或消息队列数据盘持续增长、写入已经失败，或预计 30 分钟内耗尽时，立即升级为 P1。涉及 MySQL、Elasticsearch、RabbitMQ 数据目录时必须由对应中间件负责人复核，严禁以删除数据文件作为常规释放空间手段。

## 五、验证与关闭

处置后再次检查 `df -hT`、`df -i` 和增长曲线，确认使用率降至 80% 以下或容量余量满足至少七天增长。验证应用写入、日志滚动、上传和监控恢复正常。工单中记录根因、释放空间、执行人、复核人、命令意图、业务验证和后续容量治理项。

## 六、长期治理

为日志和上传目录配置容量配额、生命周期和分级告警；建立日增长量与保留期容量模型；对容器日志启用轮转；对异常增长设置预测告警。扩容只能缓解容量压力，仍需修复日志失控、任务重复输出、备份未清理或上传缺少限制等根因。
